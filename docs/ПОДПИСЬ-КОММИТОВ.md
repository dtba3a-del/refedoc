# Подпись коммитов: что это, и почему «Unverified» — не клеймо

Вопрос автора, 2026-09-03: как пользоваться `user.signingkey` и
`commit.gpgsign true`, и что означает «недоверенные».

## 1. Что именно проверяет GitHub

Значок `Verified` не о содержании коммита и не о правах на него. Он
отвечает ровно на один вопрос: **сходится ли криптографическая подпись
коммита с ключом, который владелец учётной записи заранее объявил своим**.

Отсюда:

* **`Unverified` не значит «недостоверный».** Он значит «площадка не может
  подтвердить, что коммит сделан владельцем этого адреса». Отсутствие
  доказательства — не доказательство отсутствия.
* Подпись не даёт и не отнимает прав. Право на результат у автора и без
  подписи; подпись есть заявление о происхождении, а не о собственности.
* Ценность подписи одна и вполне земная: без неё любой может выставить
  коммит от вашего адреса — git берёт `user.email` из настройки, а не из
  удостоверения.

## 2. Подпись и авторство — разные оси

Крючок среды предлагал перевести коммиты на `noreply@anthropic.com` и имя
инструмента. Это ошибка по существу: так подпись покупается ценой отказа
от авторства, что прямо запрещено каноном профиля.

**Обе цели совместимы:** коммит остаётся за `dtba3a <dtba3a@gmail.com>`,
а подпись ставится **вашим** ключом. Тогда `Verified` подтверждает именно
то, что должно подтверждать: коммит сделан вами.

## 3. Как это включается

Проще ключом SSH — он у вас уже есть для доступа к git.

```bash
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
git config --global tag.gpgsign true
```

Затем тот же **публичный** ключ добавляется в GitHub ещё раз, но как
**Signing key** (Settings ▸ SSH and GPG keys ▸ New SSH key ▸ Key type:
Signing key). Ключ доступа и ключ подписи — разные записи, даже если файл
один.

Вариант с GPG, если нужен ключ, не привязанный к доступу:

```bash
gpg --full-generate-key                       # ed25519, без срока или со сроком
gpg --list-secret-keys --keyid-format=long    # взять идентификатор
git config --global user.signingkey <ID>
git config --global commit.gpgsign true
gpg --armor --export <ID>                     # публичную часть — в GitHub
```

Проверка: `git log --show-signature -1`.

## 4. Почему подписывать буду не я

**Приватный ключ не должен попадать в эту среду.** Контейнер эфемерный, а
канон дома прямо запрещает ключам сюда попадать — досмотрщик их и
задерживает. Значит:

* подпись ставится **на вашей машине**, где ключ и живёт;
* сессия в контейнере подписывать коммиты не может и не должна;
* коммиты сессии останутся `Unverified`, и это верное отображение
  действительности: их сделал инструмент от вашего имени по вашему
  распоряжению, а ключом распоряжаетесь вы.

Если нужна подпись задним числом на уже сделанных коммитах — она ставится
переписыванием этих коммитов на вашей машине
(`git rebase --exec 'git commit --amend --no-edit -S'`), с обычной ценой
переписывания истории.

## 5. О «вне экосистемы веры»

Замечание автора о том, что «недоверенные» — с одной стороны клеймо, с
другой комплимент, здесь буквально верно. Подпись не устанавливает истину,
она сокращает круг тех, кому приходится верить: без неё верят настройке
`user.email`, с ней — тому, что ключ не утёк. Это не выход из веры, а
перенос её в место, где её можно проверить вычислением. Ровно то же, что
делает `sha256` в переписи: не отменяет доверия, а делает его проверяемым.
