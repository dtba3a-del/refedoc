# Протокол переноса справочного материала

## 1. Что переезжает

Файлы `*.pdf`, `*.djvu`, `*.djv` из **специально оформленных справочных
каталогов** источников. Что считать таким каталогом — записано в
[`../tools/refdoc_rules.json`](../tools/refdoc_rules.json) и только там:
правило в одном месте, иначе через месяц их станет два и они разойдутся.

| Источник | Едет | Остаётся |
|---|---|---|
| `GPIBNIE7-12` | `docs/` | `inbox/from-user/` — распоряжения автора, не справочник |
| `InvesePolar` | `inbox/sci_data/`, `inbox/запрос материалов — SCI/`, `notes/материалы/` | `inbox/raw/` — рабочее сырьё бесед |
| `-Ctpu-bintape-timechannel-` | `references/`, `docs/` | — |

Порядок задан автором: `GPIBNIE7-12` → `InvesePolar` →
`-Ctpu-bintape-timechannel-` (последним, он же самый крупный).

## 2. Куда кладётся

Структура исходного каталога сохраняется под именем репозитория:

```
refedoc/<Репозиторий>/<путь как в источнике>
```

Пример: `-Ctpu-bintape-timechannel-/references/appnotes/en/Tektronix-TDS3000-datasheet.pdf`
переезжает в
`refedoc/-Ctpu-bintape-timechannel-/references/appnotes/en/Tektronix-TDS3000-datasheet.pdf`.

Переименований нет. Имя файла — часть его происхождения: по нему материал
ищут в переписке и в журналах, а переименование эту связь рвёт молча.

## 3. Что остаётся на месте

Вместо файла — указатель `<имя файла>.где.md` рядом с тем местом, где
файл лежал, и один `КУДА-ПЕРЕЕХАЛО.md` на каталог. Указатель называет:
что это было, сколько весило, sha256, куда переехало, чем открыть.

Указатели — **производное**: собираются `tools/make_pointer.py`, руками
не правятся.

## 4. Сверка после переноса

Перенос считается выполненным, когда совпали три числа: количество
файлов, суммарный вес и sha256 каждого файла — до и после. Перепись
с хешами: `python3 tools/refdoc_inventory.py --hash`.

Порядок действий: скопировать → сверить хеши → и только потом удалить из
источника. Обратный порядок однажды стоил профилю 99 МиБ дистрибутивов.
